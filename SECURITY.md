# Security reporting

Muniment is a synthetic-data Tiramisu demonstration, not an audited mainnet product. Read the [threat model](docs/threat-model.md) and [verification limits](docs/testing.md).

For a suspected vulnerability, check the repository's [Security tab](https://github.com/TheWeirdDee/muniment/security) for private vulnerability reporting. If **Report a vulnerability** is available, use it. This policy does not assert that the feature is enabled.

If no private reporting route is offered, open a minimal [issue](https://github.com/TheWeirdDee/muniment/issues) requesting a private security contact from the maintainer, without exploit details or sensitive data. Do not publish keys, tokens, personal information or a working exploit in that request. No response-time guarantee or bounty is offered.

A private report should identify the affected revision, component, prerequisites, expected/actual behavior, impact and a synthetic reproduction. Do not test against other people's records, spend their funds, exhaust public RPC quotas or publish real personal data. Historical test failures remain part of the public evidence; successful mocked tests do not establish third-party wallet compatibility.
